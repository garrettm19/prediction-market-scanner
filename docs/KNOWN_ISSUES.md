# Known Issues

This is the backlog of verified engineering findings that are still unresolved. Every item here was re-checked against the current source. Findings that have been fixed, or that review refuted, are not listed. For fixes already merged, see `git log`.

## How to read this backlog

Each row has a severity in the **Impact** column:

| Severity | Meaning |
|----------|---------|
| **High** | Can produce a wrong BUY, a wrong alert, or a wrong price/probability under realistic inputs, or can silently disable a safety gate. |
| **Medium** | Wrong or misleading output in narrower conditions, wasted Odds API credits, or degraded monitoring that is not obvious to the operator. |
| **Low** | Defense-in-depth, observability, documentation drift, or a problem that only affects a feature that is off by default. |

**False positives are treated as the most serious class of defect.** A false positive is a candidate classified BUY on the wrong event, side, line, or price. The tool supports decisions that can involve real money, so a missed opportunity is acceptable and a wrong BUY is not. Most fixes below therefore fail closed: they downgrade or drop a candidate rather than trying to rescue it.

"Model probability" means the FanDuel-implied (devigged) probability. It is an estimate from one sportsbook, not an objectively true probability. Code identifiers such as `p_true` keep their names.

Locations are relative to the repository root. Line numbers refer to the current branch and will drift as the code changes, so the function name is the stable reference.

## 3. Security posture
